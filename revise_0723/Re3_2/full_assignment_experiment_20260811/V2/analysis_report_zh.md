# 审稿意见 3.2：V2 IDBO 分配层全面实验报告

## 1. 实验范围与基准

本实验只研究 IDBO 目标分配，不运行后续强化学习制导或拦截仿真。名义基准为当前论文的 **20 架拦截器对 8 个目标**。所有场景均采用当前高亮稿的三维初始范围：拦截器位于半径 100 m 的圆盘、高度 0 m；目标位于 1500--1600 m 圆环、高度 120 m；双方速度均为 10--40 m/s。

规模扫描保持名义比例 $M/N=20/8=2.5$，取

```text
10×4, 20×8 (nominal), 40×16, 80×32, 160×64.
```

V2 优化器直接来自只读目录 `revise_0723/idbo_paper`。通信层根据正文 Top-$L_{\max}$ 胜者记录和时间戳机制单独建模，链路交换周期为 50 ms。报告中的 delay 是在一个基准交换周期之外的附加单跳时延。

## 2. 实验设计

### A. 真实优化器计算复杂度

- 种群扫描：$P=8,16,32,64$，固定 $M=20,N=8,T=20$，每点 7 次；
- 联合规模扫描：上述五种 $M\times N$，固定 $P=12,T=12$，每点 5 次；
- 报告 CPU 墙钟时间及 log--log 拟合斜率。

联合规模扫描采用相同固定预算，目的是隔离问题维数的影响；其绝对时间不能解释为不同优化预算下的实时性能上限。

### B. 静态快照下的延迟与拓扑

- 20 个随机三维 $20\times8$ 分配快照；
- 基于拦截器初始位置构造连通 2-nearest-neighbor 图，图直径为 6--12；
- 附加单跳延迟为 0、50、100、200 和 400 ms；
- 每次运行均将所有节点的最终 Top-$L_{\max}$ 胜者集合与全局固定点逐项比较。

另外在 100 ms 附加时延下使用直径 $D=1,3,4,5,10$ 的通信图，隔离考察图直径。

### C. 动态协同偏转场景

- 8 条独立序列，每条包含 30 个三维分配快照；
- 每 2 s 更新一次目标分配；
- 目标围绕指向防区中心的航向执行分组、交替侧向偏转，偏转角为 $\pm0.42$ rad，每 2.5 s 切换，并叠加 $\pm2$ m/s 垂向速度；
- 每个快照使用 V2 IDBO 重新生成投标和名义胜者集合；
- 统计赢家集合 Jaccard 一致率、节点完全一致率、边不一致度、陈旧记录率，以及在下一次 2-s 更新前恢复到 95% 节点一致的比例。

该动态场景是通信跟踪压力测试，不包含交战结局或拦截成功率。

## 3. 复杂度核查

当前 NumPy 参考实现的候选解为 $P\times M\times N$ 偏好矩阵。`Scenario.advantage()` 对每个目标构造 $M\times M$ 竞争矩阵，因此完整参考实现的主要上界为

```text
O(T P N M^2)
```

并带有 $O(TP\log P)$ 的候选排序开销。该表达描述当前全局参考代码，不应与每机只处理有界邻域的部署复杂度混为一谈。

对于每机邻域度为 $\Delta_i$ 的分布式实现，竞争求和局限于邻域时，本地主要开销为

```text
O(T P N Δ_i).
```

每次共识交换的 Top-$L_{\max}$ 合并开销为

```text
O(N Δ_i L_max log(Δ_i L_max)),
```

通信载荷为 $O(N\Delta_iL_{\max})$ 条记录。并行传播所有目标的静态胜者记录需要 $O(D(d+1))$ 轮；采用逐目标 bundle 构造时，$O(ND(d+1))$ 是保守上界。

## 4. V2 实测结果

### 4.1 优化器规模

种群扫描的拟合斜率为 **0.84**，说明在固定 $20\times8$ 场景中，运行时间随 $P$ 近似线性增长。联合扩大 $M$ 与 $N$ 时斜率为 **1.45**，表明当前全局参考实现呈亚二次但明显超线性增长，不能写成无条件线性。

| $M\times N$ | IDBO time (s) | Graph diameter | Consensus time at 100 ms (s) | Messages to consensus |
|---:|---:|---:|---:|---:|
| 10×4 | 0.031 | 3 | 0.55 | 400 |
| **20×8** | **0.048** | **5** | **0.85** | **1,280** |
| 40×16 | 0.091 | 10 | 1.60 | 4,960 |
| 80×32 | 0.273 | 20 | 3.10 | 19,520 |
| 160×64 | 1.948 | 40 | 6.10 | 77,440 |

有界度环图下，每轮有向消息数随 $M$ 线性增长，但图直径也随 $M$ 增大，因此完成整次共识的累计消息数和延迟并非线性。该结果比“共识时间与蜂群规模无关”更严谨。

### 4.2 静态时延

| Additional delay (ms) | Static consensus time (s) | Fixed-point verification |
|---:|---:|---:|
| 0 | $0.53\pm0.08$ | 100% |
| 50 | $0.96\pm0.17$ | 100% |
| 100 | $1.39\pm0.25$ | 100% |
| 200 | $2.25\pm0.42$ | 100% |
| 400 | $3.97\pm0.76$ | 100% |

拟合关系为约 $0.53+0.0086\tau$ s，其中 $\tau$ 以 ms 为单位。直径实验得到约 $0.10+0.15D$ s；$0.15$ s/hop 正好对应 100 ms 附加时延加 50 ms 基准交换周期。

因此，静态快照下时延不改变经核验的固定点，但按每跳传播时间和图直径增加共识延迟。

### 4.3 动态偏转

| Additional delay (ms) | Winner-set agreement | Recovery before next 2-s update |
|---:|---:|---:|
| 0 | $0.938\pm0.017$ | 100.0% |
| 50 | $0.876\pm0.034$ | 100.0% |
| 100 | $0.814\pm0.051$ | 100.0% |
| 200 | $0.697\pm0.075$ | 41.2% |
| 400 | $0.545\pm0.084$ | 0.9% |

在该压力测试中，100 ms 及以下的附加时延仍能在每个 2-s 重分配周期内恢复；200 ms 开始进入明显的时标冲突区，400 ms 时大部分更新无法在下一次几何变化前传播完毕。这个结果说明“静态最终收敛”并不等价于“动态环境中始终可用”。实际部署应满足

```text
consensus time < reallocation interval.
```

## 5. 建议用于回复审稿人的结论

1. 不宣称算法对时延不敏感；应说明时延对共识时间具有可预测的近线性影响。
2. 静态条件下，在连通图、有限时延和消息最终送达时，所有实验都达到相同固定点。
3. 动态偏转条件下存在明确边界：本实验中 0--100 ms 仍可在 2 s 内恢复，200--400 ms 显著降低实时跟踪能力。
4. 当前全局 V2 参考实现随联合问题规模呈约 $M^{1.45}$ 的实测增长；分布式部署的每机开销由邻居度而不是总蜂群规模直接控制，但网络直径仍控制总体共识时间。
5. 20×8 是论文基准；更大规模结果仅用于检验扩展趋势。
